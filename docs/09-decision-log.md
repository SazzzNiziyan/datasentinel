| D-09 | Account linking (Q-01)                                               | When an external sign-in (Google/GitHub) matches an existing account's email, link automatically only if the provider reports that email as verified (Google `email_verified`; GitHub verified primary email). If the existing account's own email was never verified, do not keep its password: remove it on linking and require a reset. Unverified provider emails never link.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Decided | 2026-10-16 |
| D-10 | CSV dataset identity and freshness (Q-06)                            | On upload, the user explicitly selects an existing dataset or creates a new one; filenames are never used to match. An upload whose columns differ from the dataset's last schema is still attached, but runs schema-drift detection and shows the drift before profiling results are trusted. Freshness defaults to the upload time; a dataset may instead name a timestamp column, and freshness then uses its maximum value.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Decided | 2026-10-16 |
| D-11 | Source deletion (Q-08)                                               | Delete means archive by default: scheduled checks stop, the source becomes `archived`, and its history stays readable. Owner or Administrator may additionally purge an archived source: stored credentials and uploaded raw files are destroyed, while incidents, check results, evidence summaries, and audit records are kept. Purge requires typed confirmation, cannot be undone, and writes an audit entry.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | Decided | 2026-10-16 |
| D-12 | Package manager and monorepo tool                                    | pnpm 12.14.0 workspaces, pinned with `packageManager` in the root `package.json` (pnpm switches itself to that version). Node 26 no longer bundles Corepack, so pnpm is installed with `npm install -g pnpm`. Node version is enforced by `engineStrict: true` in `pnpm-workspace.yaml`, because pnpm 11+ ignores `.npmrc` for this. No Turborepo/Nx for now: `pnpm -r` and `--filter` are enough until build caching is a real need.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Decided | 2026-10-17 |
| D-13 | TypeScript version and strictness                                    | TypeScript 6 (`~6.0.3`) everywhere. TS 7.0 has no JavaScript compiler API, so `nest build`, typescript-eslint and ts-jest cannot run on it; revisit when TS 7.1 restores an API. Configs avoid options TS 7 removed (`baseUrl`, `node10` resolution) so upgrading is a version bump. Shared `tsconfig.base.json`: `strict` plus `noUncheckedIndexedAccess`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noUnusedLocals`, `noUnusedParameters`; not `exactOptionalPropertyTypes`. All packages are ESM. `contracts` and `config` are built composite packages with a `@datasentinel/source` export condition for build-free development; erasable syntax only; no `isolatedDeclarations` (it forbids the inferred zod schema types these packages are built on). API/worker keep decorator metadata and disable `strictPropertyInitialization` (official Nest template).                                                                                                                                                                                                                                                                                                        | Decided | 2026-10-17 |
| D-14 | Lint and format                                                      | ESLint 10 flat config + typescript-eslint `recommendedTypeChecked` (type-aware through the project service, on the repo's TS 6) + react-hooks 7 + Prettier 3. Chosen over oxlint and Biome after testing: their `--fix` rewrites NestJS injected classes to `import type` and breaks injection, and Biome's promise rules miss Node built-ins. Trade-off: about 7x slower than oxlint. Respect pnpm's minimum release age; do not add `minimumReleaseAgeExclude` entries. LF line endings via `.gitattributes`. `pnpm check` runs typecheck, lint, format check, and tests.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Decided | 2026-10-17 |
| D-15 | Design tokens and contrast fixes                                     | Tokens are CSS custom properties in `apps/web/src/styles/tokens.css`: palette values plus semantic names; components use only semantic names. Starter palette kept. Yellow warning shapes always carry an ink outline (bare yellow is 1.4:1 on paper). Status is always shape plus word: circle healthy, outlined triangle warning, square critical, diamond info. | D-16 | App shell and routing                                                | React Router 8 (library mode, `BrowserRouter`) with one route per navigation entry; the shell is a layout route. | D-17 | Reusable components and severity levels                              | Severity has three levels, Critical (square), Warning (outlined triangle), Info (diamond), matching the status tokens; which levels open an incident stays open (Q-02). `StatusMark` takes a tone (healthy, warning, critical, info, neutral ring) plus the caller's words; domain states map to tones where the domain is defined. `SeverityBadge` is boxed so severity and status never look alike. `MetricBlock` states the expectation and the gap ("4,860 below expected (69%)"). `DataTable` has sortable columns, loading/error/empty states, and a critical mark on load errors. `ConfirmActionDialog` uses native `<dialog>`, names target, effect, and permission, cannot run twice, can require typing the target (D-11), and never shows upstream error text. Components are built test-first with Vitest + happy-dom + Testing Library; dev-only galleries at `/dev/components` and `/dev/tokens`.
