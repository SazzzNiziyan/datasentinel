| D-23  | Request IDs and structured logs                                                    | `nestjs-pino` writes one JSON line per request (pino; stdout). Every response carries `x-request-id`: a caller's value is reused only if it matches `[A-Za-z0-9._:-]{1,128}`, otherwise a UUID is generated; the same ID is the log's `req.id`. Request logs keep only ID, method, path (query string dropped), status, and timing; headers are never logged (cookies, tokens, OAuth codes). Fields named password/secret/token/accessToken/refreshToken/apiKey/authorization/cookie/connectionString are censored up to two levels deep as a second line of defense. Error messages and stacks pass through `scrubSecrets`, which removes credentials from URLs (`scheme://user:pass@` becomes `scheme://[redacted]@`); startup crashes are scrubbed the same way. Log level from `LOG_LEVEL`. `AppModule.register({ logLevel, logStream })` lets tests silence or capture logs. Workspace/user IDs join the log context with sign-in (Phase E).
